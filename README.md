# 悦安月子中心 · 产妇护理计划与家属探访平台

月子中心业务一体化平台：覆盖**入住登记 → 护理计划执行 → 多角色协同异常处置 → 家属探访/授权查看 → 出所结算 → 出所后随访与复购转介绍**全流程。所有角色（护理师、护士长、儿科医生、营养师、产康师、月嫂、前台、财务、家属、中心管理者）围绕**同一间房**协同工作。

## 技术栈

- **Next.js 15（App Router, TypeScript）**：服务端渲染页面 + API 路由（前后端一体）
- **数据库**：Node 22 内置 `node:sqlite`（文件库 `data/mcare.db`，首次启动自动建表+播种演示数据）。SQL 均为标准语法，表结构可直接迁移到 MySQL（将 `datetime('now','localtime')` 默认值替换为 `CURRENT_TIMESTAMP` 即可）
- **认证**：HMAC 签名 httpOnly Cookie 会话，SHA-256 加盐口令哈希
- 无外部服务依赖，克隆后安装依赖即可运行

## 本地启动

### 方式一：Docker 一键启动（推荐）

```bash
docker compose up --build -d   # 构建并后台启动
# 打开 http://localhost:3000
docker compose logs -f mcare   # 查看日志
docker compose down            # 停止（SQLite 数据持久化在 mcare-data 卷中）
```

镜像基于 `node:22-bookworm-slim`（内置 `node:sqlite`），多阶段构建；数据库文件持久化在 Docker 卷 `mcare-data`，删除容器不丢数据。生产环境请通过环境变量 `MCARE_SECRET` 覆盖会话签名密钥。

### 方式二：本机 Node 运行

```bash
npm install        # 安装依赖（Node.js ≥ 22.5，需内置 node:sqlite）
npm run dev        # 开发模式 http://localhost:3000
# 或生产模式：
npm run build && npm start
```

首次启动自动创建 `data/` 并写入演示数据（含在住订单 2 个、已出所订单 1 个、各角色账号）。删除 `data/` 目录即可重置为初始演示数据。
> 探访演示场景（已确认下午探访、待处理冲突申请、待确认临时授权、在房/已失效门禁）锚定**运行当天**日期生成，任何一天启动都有完整的冲突/门禁协同数据可演练。

### 探访冲突 / 授权 / 门禁协同（本次新增）

业务规则（`src/lib/visits.ts` 排期引擎 + `src/lib/actions.ts` 原子动作）：

1. **冲突检测**：多个家属申请同一时段、而房间有人数上限（`rooms.capacity`）时，平台综合
   **产妇授权关系、探访规则、房间容量、护理避让时段（查房/伤口/乳房/产康）与婴儿护理安排（宝宝洗澡/托管）**
   生成方案，类型为 `queue`（排队放行）/ `split`（拆分时段）/ `reschedule`（改约次日）；同一时刻在房峰值不得超过房间容量（事件扫描精确校验）。
2. **门禁前置三条件**：同一申请若存在 **临时授权未经产妇确认 / 探访人健康异常或未核验 / 入所消毒未完成 / 无授权**，方案确认时被原子拦截，**不直接分配门禁**，原预约保留并生成「探访门禁协同受阻」异常工单转人工。
3. **原子确认**：前台确认方案后，**门禁有效期 + 访客名单（含排队号）+ 护理避让安排**在单个数据库事务内同成同败，返回事务号；任一环节失败整体回滚、保留原预约并提示人工处理，杜绝「门禁已开而护理计划未调整」。
4. **授权撤回**：产妇可在探访前撤回授权——**未入场家属门禁立即失效并通知前台**；若家属**已入场**，不自动关门，而是升级**护士长现场协调**（critical 工单），护士长陪同离场后回收门禁、记录出场并结案。
5. **爽约与覆盖**：未按约到场登记爽约，同名探访人后续预约排队优先级自动下调；前台可基于**紧急照护需要**或**产妇书面确认**覆盖该限制，必须填写理由并留痕。
6. **闭环判定**：活动结束后，由 **门禁进出记录（必须有入有出）+ 实际探访人数 + 护理避让结果全部确认**共同决定能否闭环；人未离场、无入场记录或有护理避让未确认，均不能闭环。

> 排期优先级：授权关系（常规家属优先于临时）→ 历史爽约降级 → 申请顺序；探访需求优先，护理查房为其避让（紧急护理除外）。

### 手工验证路径建议（探访协同）

1. `front` 登录 `/frontdesk` → 今日 801 房已有张强、李秀兰下午探访（容量已满），张磊/刘芳待处理
2. 点「生成协同方案」→ 看到 `张磊/刘芳` 带红色前置阻断项；直接「前台确认方案」→ 被拦截并提示保留原预约
3. `family1` 登录 `/family` →「探访授权管理」为两位临时家属**授予并确认**临时授权；回前台对两人做健康核验 + 消毒登记 → 重新生成方案 → 确认原子生效，获得门禁码与护理避让联动
4. 前台「门禁台」输入无效码被拒；用有效码可在窗口前 30 分钟内入场、出场
5. `family1` 撤回张强授权（其未入场）→ 门禁立即变「已失效(撤回)」，前台收到通知
6. 对李秀兰登记爽约 → 再预约看到优先级下调；前台凭产妇书面确认覆盖并留理由
7. 全新房间走完整链路：入场 →（产妇在场撤回）护士长协调离场 → 护理避让未确认时闭环被阻止 → 护理师确认避让 → 预约闭环

## 功能地图（需求 → 实现）

- **入住档案**：分娩方式、产后天数、过敏史、哺乳方式、宝宝体重、黄疸观察、房型套餐、餐食禁忌、家属探访权限、医生建议（前台入住登记表单，自动建护理计划/赠品/费用/家属账号）
- **护理安排**：查房、伤口观察、乳房护理、产康课程、月子餐、宝宝洗澡抚触、夜间照护（护理计划+每日任务，护士长可增改）
- **家属端**：经授权的护理摘要（仅可见标记记录）、探访预约（含临时探访）、**探访授权授予/确认/撤回**、**我的门禁与进出记录**、费用明细、意见反馈、随访安排、与中心留言
- **探访冲突协同**（容量/授权/护理避让/婴儿护理 → 排队·拆分·改约）：健康核验与入所消毒前置三条件、方案原子确认（门禁有效期+访客名单+护理避让同成同败，失败回滚保留原预约转人工）、门禁进出留痕与有效期校验、产妇撤回授权（未入场立即失效通知前台/已入场升级护士长协调）、爽约降级与前台凭紧急照护或产妇书面确认覆盖留痕、活动闭环（进出记录+实到人数+避让结果共同判定）
- **异常协同**（围绕同一间房，工单+时间线+角色路由）：黄疸升高→儿科；乳腺堵塞/记录质疑/退所争议→护士长；临时探访/门禁协同受阻→前台（同步护士长）；月嫂请假→护士长改派；餐食忌口→营养师（配餐自动核对）；产康延期→产康师；套餐升级/提前退所→费用折算+工单；撤回授权时访客已在场→护士长紧急协调
- **出所后**：护理计划与异常记录留存、费用结算单、回访/母婴随访计划、复购与转介绍线索
- **其他**：套餐赠品发放、产康师排班、宝宝托管日志、探访消毒与健康核验登记、房间升级（自动换房+补差价）、医生巡诊记录
- **管理者**：按房间聚合护理动作、家属沟通、费用变化、异常处置；高敏感客诉区（记录质疑/退所争议/忌口异常/低分反馈）；口碑均分
- **反馈联动**：家属反馈可被护士长标记"影响护理师排班"，低分反馈进入管理看板；护理记录进入出所后母婴随访；退所争议自动同步护士长
