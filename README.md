# 悦安月子中心 · 产妇护理计划与家属探访平台

月子中心业务一体化平台：覆盖**入住登记 → 护理计划执行 → 多角色协同异常处置 → 家属探访/授权/门禁协同 → 出所结算 → 出所后随访与复购转介绍**全流程。所有角色（护理师、护士长、儿科医生、营养师、产康师、月嫂、前台、财务、家属、中心管理者）围绕**同一间房**协同工作。

## 技术栈

- **Next.js 15（App Router, TypeScript）**：服务端渲染页面 + API 路由（前后端一体）
- **数据库**：Node 22 内置 `node:sqlite`（文件库 `data/mcare.db`，首次启动自动建表+播种演示数据；旧库启动时自动 `ALTER TABLE` 迁移补列）。SQL 均为标准语法，表结构可直接迁移到 MySQL（将 `datetime('now','localtime')` 默认值替换为 `CURRENT_TIMESTAMP` 即可）
- **认证**：HMAC 签名 httpOnly Cookie 会话，SHA-256 加盐口令哈希
- 无外部服务依赖，克隆后安装依赖即可运行

## 本地启动

### 方式一：Docker 一键启动（推荐）

```bash
docker compose up --build -d      # 构建并后台启动
open http://localhost:3000        # 浏览器访问
docker compose logs -f            # 查看日志
docker compose down               # 停止（数据保留在 mcare-data 卷中）
```

镜像基于 `node:22-bookworm-slim` 多阶段构建，运行 Next.js standalone 产物；SQLite 数据库持久化在 `mcare-data` 卷（容器内 `/app/data`）。修改 `docker-compose.yml` 中的 `MCARE_SECRET` 以设置生产会话密钥。

### 方式二：本地 Node 运行

```bash
npm install        # 安装依赖（Node.js ≥ 22.5，需启用内置 node:sqlite）
npm run dev        # 开发模式 http://localhost:3000
# 或生产模式：
npm run build && npm start
```

首次启动自动创建 `data/` 并写入演示数据（含在住订单 2 个、已出所订单 1 个、各角色账号、10-02 探访冲突演示场景）。删除 `data/` 目录即可重置为初始演示数据。

## 验证方式

### 自动化冒烟（已实际执行）

```bash
npm run build && npm start   # 终端1：构建并启动
npm run smoke                # 终端2：85 项冒烟断言
# 或对已启动的任意实例（含容器）执行：
SMOKE_BASE=http://localhost:3000 npm run smoke
```

`scripts/smoke.mjs` 覆盖：登录页可访问、错误密码拒绝、10 个角色登录并进入各自工作台、未登录/越权重定向、房间360视图、护理任务创建与完成、配餐命中忌口自动生成异常、家属临时探访生成异常工单、家属质疑护理记录、家属越权访问他房被拒、前台入住登记（含家属账号开通与登录）、财务增项/提前退所/结算确认、家属反馈与护士长回复标记影响排班、管理看板高敏感客诉区；以及 **#16 探访冲突/授权/门禁协同全链路（41 项断言）**：

- 产妇常规/临时授权登记与"书面确认生效"；5 份同一时段（14:00，房间容量 2）探访申请
- 健康核验（1 人发热）与消毒登记；**临时授权未确认/健康异常/消毒未完成 → 阻断，不下发门禁**
- 冲突求解：按授权关系+爽约历史计算优先级 → 2 人原时段、2 人改约、1 人阻断转人工
- 前台确认方案：**门禁有效期 + 访客名单 + 护士查房避让在同一 SQLite 事务原子更新**；冲突护理任务改期
- 方案生成后授权/健康状态变化 → 确认原子中止、零门禁/零避让写入、护理任务未动、原预约全部保留
- 探访前撤回授权：未入场家属门禁立即失效并通知前台；已入场撤回 → 升级护士长，门禁不远程失效，现场协调后离场
- 门禁入场/离场（有效期校验）；护理回填避让结果
- 闭环判定：门禁进出配对 + 实际探访人数 + 护理避让齐备为健康闭环；进出不配对判异常，护士长可人工核销
- 爽约登记（门禁失效、影响后续优先级）；前台凭"紧急照护/产妇书面确认"覆盖限制且必须留理由（无理由被拒）

## 功能地图（需求 → 实现）

- **入住档案**：分娩方式、产后天数、过敏史、哺乳方式、宝宝体重、黄疸观察、房型套餐、餐食禁忌、家属探访权限、医生建议（前台入住登记表单，自动建护理计划/赠品/费用/家属账号）
- **护理安排**：查房、伤口观察、乳房护理、产康课程、月子餐、宝宝洗澡抚触、夜间照护（护理计划+每日任务，护士长可增改）
- **家属端**：经授权的护理摘要（仅可见标记记录）、探访授权管理（常规/临时，产妇书面确认生效、可撤回）、探访预约、门禁凭证与进出记录、费用明细、意见反馈、随访安排、与中心留言
- **探访冲突 / 授权 / 门禁协同**：
  - 多个家属申请同一时段、超过房间限员时，按**产妇授权关系 + 爽约历史**计算优先级，结合房间容量、固定护理/婴儿护理窗口，自动给出**原时段 / 拆分时段 / 改约 / 排队**方案
  - **临时授权未经产妇确认、探访人健康异常、入所消毒未完成**的申请一律不直接分配门禁，保留原预约并提示人工处理
  - 前台确认方案后，**门禁有效期、访客名单、护士查房避让时间在同一事务原子更新**；冲突护理任务自动改期。任一环节失败全部回滚（门禁不会"已开"而护理计划未调整）
  - 产妇探访前撤回授权：未入场家属门禁**立即失效**并通知前台；探访人**已入场**的撤回升级护士长现场协调，门禁不远程失效
  - 家属未按约到场记**爽约**并下调后续排队优先级；前台可凭**紧急照护或产妇书面确认**覆盖该限制且必须留理由
  - 活动结束后由**门禁进出记录 + 实际探访人数 + 护理避让结果**共同判定预约是否闭环；异常闭环由护士长人工核销
- **异常协同**（围绕同一间房，工单+时间线+角色路由）：黄疸升高→儿科；乳腺堵塞/记录质疑/退所争议/撤回授权时探访人在场→护士长；临时探访→前台；月嫂请假→护士长改派；餐食忌口→营养师（配餐自动核对）；产康延期→产康师；套餐升级/提前退所→费用折算+工单
- **出所后**：护理计划与异常记录留存、费用结算单、回访/母婴随访计划、复购与转介绍线索
- **其他**：套餐赠品发放、产康师排班、宝宝托管日志、探访消毒登记、房间升级（自动换房+补差价）、医生巡诊记录
- **管理者**：按房间聚合护理动作、家属沟通、费用变化、异常处置；高敏感客诉区（记录质疑/退所争议/忌口异常/低分反馈）；口碑均分
- **反馈联动**：家属反馈可被护士长标记"影响护理师排班"，低分反馈进入管理看板；护理记录进入出所后母婴随访；退所争议自动同步护士长

## 环境变量（可选）

- `MCARE_DB`：数据库文件路径（默认 `./data/mcare.db`；容器内为 `/app/data/mcare.db`）
- `MCARE_SECRET`：会话签名密钥（生产环境务必设置，compose 中通过环境变量注入）
- `PORT` / `HOSTNAME`：监听端口与地址（容器默认 `3000` / `0.0.0.0`）
